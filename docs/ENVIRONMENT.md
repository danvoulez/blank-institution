# Environment reference

The project runs one Nuxt application plus the Eve service generated by `eve/nuxt`. On Vercel, project environment variables are available to both generated services. On a split self-hosted deployment, set the shared variables on both processes and keep role-provider secrets on the Eve process.

## Required core variables

| Variable | Required | Purpose |
|---|---:|---|
| `BETTER_AUTH_SECRET` | yes | Signs Better Auth sessions and tokens. Generate a long random value. |
| `BETTER_AUTH_URL` | yes | Public origin of the Nuxt application, for example `http://localhost:3000`. |
| `INTERNAL_API_SECRET` | yes | Authenticates Eve ↔ Nuxt internal calls and Nuxt's official Eve Client role sessions. Use the identical value on both services. |
| `PROCESS_API_TOKEN_SALT` | yes for API/MCP | Server-side salt used to hash user-scoped process API tokens. Changing it invalidates existing tokens. |

Generate secrets with a cryptographically secure tool, for example:

```bash
openssl rand -base64 48
```

## Database

Local development uses NuxtHub's SQLite database under `.data/` when Turso variables are absent.

| Variable | Required | Purpose |
|---|---:|---|
| `TURSO_DATABASE_URL` | production/serverless | Hosted libSQL database URL. |
| `TURSO_AUTH_TOKEN` | production/serverless | Hosted libSQL token. |

Run migrations after configuring the target database:

```bash
pnpm db:migrate
```

## Role model routing

Each role can use an AI Gateway model ID or an OpenAI-compatible endpoint. Settings → Runtime can persist model ID, routing mode, base URL, and context window for **new sessions**. API keys are never stored in the database and remain environment secrets.

| Variable | Default | Purpose |
|---|---|---|
| `TRANSLATOR_MODEL` | `anthropic/claude-sonnet-4.6` | Premium live-chat model. |
| `TRANSLATOR_BASE_URL` | empty | Makes Translator use an OpenAI-compatible endpoint when set. |
| `TRANSLATOR_API_KEY` | empty | Direct-provider secret. |
| `TRANSLATOR_CONTEXT_WINDOW_TOKENS` | `200000` | Explicit context-window override. |
| `SUPERVISOR_MODEL` | `anthropic/claude-opus-4.6` | Premium asynchronous process owner/reviewer model. |
| `SUPERVISOR_BASE_URL` | empty | Direct OpenAI-compatible endpoint when set. |
| `SUPERVISOR_API_KEY` | empty | Direct-provider secret. |
| `SUPERVISOR_CONTEXT_WINDOW_TOKENS` | `200000` | Explicit context-window override. |
| `EXECUTOR_MODEL` | `qwen3-coder` | Large local execution model ID. |
| `EXECUTOR_BASE_URL` | empty | OpenAI-compatible local inference origin, normally ending in `/v1`. |
| `EXECUTOR_API_KEY` | empty | Local provider token; use the value required by the inference server. |
| `EXECUTOR_CONTEXT_WINDOW_TOKENS` | empty | Usable window for this role, as the endpoint reports it. |
| `METABOLISM_MODEL` | `qwen3-8b` | Small local liveness model ID. |
| `METABOLISM_BASE_URL` | empty | OpenAI-compatible local inference origin. |
| `METABOLISM_API_KEY` | empty | Local provider token. |
| `METABOLISM_CONTEXT_WINDOW_TOKENS` | `2048` | Usable window for this role. Set it to what the endpoint reports, not the model's nominal context: llama.cpp divides `--ctx-size` across `--parallel` slots. |

When a role has no base URL, Eve selects its serializable Gateway model at `session.started`. With a base URL, Eve creates the direct AI SDK model at `step.started`, which is the lifecycle that permits live model objects.

## Process policy

| Variable | Default | Purpose |
|---|---|---|
| `SLA_URGENT_HOURS` | empty | Institution-wide urgent duration. Without it, opening must provide an explicit `dueAt`. |
| `INTERNAL_ORIGIN` | `http://127.0.0.1:$PORT` | Where the institution reaches itself. Keep it on loopback: `BETTER_AUTH_URL` is the public name and must not be reused here. |
| `INTAKE_ANALYSIS_MAX_ATTEMPTS` | `3` | Automatic Translator analysis attempts before explicit failure and human escalation. |
| `METABOLISM_SCHEDULE` | `*/5 * * * *` | Declared cadence. Declarative only: `eve/nuxt` does not compile schedules into the Nitro build, so an external timer drives the tick. |
| `METABOLISM_LEASE_SECONDS` | `300` | How long one tick holds the liveness lease before another may take it. |
| `METABOLISM_RESERVE_OUTPUT_TOKENS` | `512` | Held back from the window for the model's reply. |
| `METABOLISM_PROMPT_OVERHEAD_TOKENS` | `320` | Tokens the surrounding instructions cost, excluded from the record budget. |
| `METABOLISM_MAX_DIGEST_RECORDS` | `25` | Hard cap on processes per tick, regardless of what would fit. |
| `ASSIGNMENT_MAX_ATTEMPTS` | `3` | Automatic assignment reissues before the type owner gets a recovery checkpoint. |
| `ASSIGNMENT_ACCEPT_MINUTES` | `10` | Time allowed to claim a newly issued assignment. |
| `ASSIGNMENT_LEASE_MINUTES` | `30` | Default renewable assignment lease. |
| `INSTITUTION_ADMIN_USER_IDS` | empty | Comma-separated Better Auth user IDs allowed to change global role routing. In production, an empty value makes Runtime settings read-only. |
| `EVE_INTERNAL_ORIGIN` | app origin | Optional root origin of a separately hosted Eve deployment. Do not include `/eve/v1`. |

## Slack

The existing Slack channel uses Vercel Connect for inbound operation. Human checkpoint notifications additionally use the bot Web API and therefore require the Slack bot credential to be available to the runtime used by `process-notifications.ts`.

Account links are stored through the existing Slack linking flow. A failed Slack notification never removes the canonical web assignment.

## Sendblue / iMessage

| Variable | Required | Purpose |
|---|---:|---|
| `SENDBLUE_API_KEY` | for iMessage | Sendblue API key. |
| `SENDBLUE_API_SECRET` | for iMessage | Sendblue API secret. |
| `SENDBLUE_FROM_NUMBER` | for iMessage | Institution Sendblue line in E.164 form. |
| `SENDBLUE_WEBHOOK_SECRET` | recommended | Compared with the `sb-signing-secret` request header. |
| `SENDBLUE_ALLOWED_SERVICES` | no | Comma-separated accepted services; defaults to `iMessage`. |
| `SENDBLUE_STATUS_CALLBACK_URL` | no | Optional outbound delivery callback. |

Configure the receive webhook at:

```text
https://YOUR_ORIGIN/eve/v1/sendblue/webhook
```

Users must link their own E.164 number in Settings → Profile.

## Public site and deployment

| Variable | Required | Purpose |
|---|---:|---|
| `NUXT_PUBLIC_SITE_URL` | optional | Canonical public origin when different from `BETTER_AUTH_URL`. |
| `EVE_NUXT_PRODUCTION_ORIGIN` | non-Vercel split host | Separate Eve origin supported by `eve/nuxt`. |
| `EVE_NUXT_PRODUCTION_PORT` | optional | Eve production port override on non-Vercel hosts. |

There is intentionally no legacy `experimentalServices` configuration. `eve/nuxt` generates the stable Eve service and `/eve/v1/**` routes during the Vercel build.
