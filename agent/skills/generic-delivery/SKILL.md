# Generic delivery process

Use this process when the request has a concrete final deliverable and no more specific Process Skill applies.

## Translator

Normalize the request without deciding whether the work is acceptable. Preserve the requester's constraints, source material, intended audience, and output format. Send the normalized intake to the Supervisor.

## Supervisor — opening checkpoint

Define all of the following before work starts:

- a concrete deliverable;
- objective acceptance criteria;
- the type owner: Supervisor or explicitly identified Human;
- the current responsible: Executor or explicitly identified Human;
- a deadline class and resolved due date;
- a bounded work order for the first assignment.

Never open a process with placeholders such as "do the task well" or "as requested".

## Executor

Accept the assignment before working. Use Eve's built-in sandbox and file tools. Store relevant outputs in the dossier, then submit a structured result with limitations and artifact identifiers. Do not approve your own work or select your successor.

## Supervisor — review checkpoint

Review only against the recorded acceptance criteria. Choose one explicit decision:

- `return`: corrections are required and the same responsible should retry;
- `reassign`: another responsible should perform the next work segment;
- `escalate`: authority or missing information must move upward;
- `complete`: the deliverable is accepted and closure is justified;
- `cancel` or `fail`: terminal outcome with a recorded reason.

A returned assignment must include actionable corrections.
